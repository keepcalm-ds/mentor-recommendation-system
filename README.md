# Mentor-Mentee Matching System

## 0. ОБЗОР ПРОЕКТА
Mentor-Mentee Matching System - рекомендательная система которая автоматически подбирает топ-5 менторов для каждого менти. Алгоритм оценивает каждую пару по четырём факторам: схожесть навыков, близость IT-областей, стаж и рейтинг ментора. Пользователь настраивает приоритеты через слайдеры (1–5), система рассчитывает индивидуальные веса.

Структура пайплайна:

| :--- | :---: | ---: |

## 1. ДАННЫЕ И ИХ ОСОБЕННОСТИ
### 1.1 Состав датасета
| Файл | Строк | Сожержание | 
| :--- | :---: | ---: |
| mentees.csv | 5000 | профили менти: level, domain, profession, skills, goal, language, format |
| mentors.csv | 2000 | профили менторов: + experience_years, available, boosted, boost_k |
| mentors_ratings.csv | 2000 | рейтинги: N(3.8, 0.7) в диапазоне [1, 5] |

### 1.2 Пропуски в данных
~35% менти и ~32% менторов имеют хотя бы один пустой атрибут. Это реалистичная ситуация для любой платформы - пользователи не заполняют профили полностью.

!!! Почему не удаляем профили с пропусками? Потому что это исключило бы треть пользователей. Вместо этого применяем честное наказание: система даёт рекомендации, но score ниже — стимул заполнить профиль.

### 1.3 Структура данных о менторах 

| Поле | Описание | Использование |
| :--- | :---: | ---: |
| level | junior/middle/senior/lead | Только в жесткой фильтрации - не в формуле score |
| skills | Навыки через ';' | Jaccard similarity с навыками менти |
| experience_years | Стаж в годах | Нормализуется: log(years+1)/log(21) |
| domain + profession | IT-область и должность | domain_vector через онтологию |
| available | Доступен ли для менторства | Жесткая фильтрация |
| boosted + boost_k | Платное продвижение | Буст финального score, если organic >= 0.3 |

## 2. Онтология (тетрадка 1_ontology.ipynb)
Онтология строится автоматически из данных — никаких ручных словарей. Это важно: если добавить новые профессии или домены, достаточно перезапустить тетрадку 1.

Три шага построения
•	Skill - Domain индекс: для каждого навыка считаем как часто он встречается у пользователей каждой области. Нормируем — получаем распределение навыка по областям.
•	Role - Domain mapping: для каждой профессии агрегируем навыки всех ее носителей через skill - domain индекс. Результат — вектор из 10 весов, показывающий насколько профессия близка к каждой области.
•	Матрица похожести 10х10: cosine similarity между частотными векторами навыков областей. Используется в формуле domain_sim — чем похожее области, тем выше вклад в score.

> MLOps Engineer  → {Data Science: 0.67, DevOps: 0.15, Backend: 0.08, ...}
> Flutter Dev     → {Mobile: 0.80, Frontend: 0.15, Backend: 0.05} 

*Почему не вручную? Ручное заполнение онтологии субъективно и не масштабируется. Автоматическое построение из данных адаптируется к реальному употреблению навыков на платформе.*

## 3. Предобработка (тетрадка 2_preprocessing.ipynb)
| Шаг | Что делается | Почему именно так |
| :--- | :---: | ---: |
| Нормализация навыков | Нижний регистр, trim пробелов | 'Python' и 'python' — один навык | 
| Кодирование level | junior=1, middle=2, senior=3, lead=4 | Для сравнения в фильтрации | 
| Кодирование языка/формата | Текст → множества: 'ru+en'→{'ru','en'} | None = совместим с любым — не блокирует | 
| Domain_vector | Профессия → 10-мерный вектор через role→domain mapping | Основа для domain_sim | 
| Experience_norm | log(years+1)/log(21) | Логарифм сглаживает: 1 год vs 5 лет важнее чем 15 vs 20 | 

*Почему логарифм для стажа? Разница между 0 и 3 годами гораздо важнее чем между 15 и 18. Логарифм отражает убывающую отдачу от опыта.*

## 4. Алгоритм скоринга (тетрадка 3_scoring.ipynb)
### 4.1 Жёсткая фильтрация
Выполняется до любых вычислений. Level используется ТОЛЬКО здесь и больше нигде:
•	available = False → исключается
•	level_mentor ≤ level_mentee → исключается
•	Язык несовместим → исключается
•	Формат несовместим → исключается
### 4.2 Четыре фактора
| Фактор | Метод | Формула | При пропуске | 
| :--- | :---: | ---: |
| skill_sim | Jaccard similarity | |A ∩ B| / |A ∪ B| | = 0, штраф w_skill×1.0 |
| domain_sim | Квадратичная форма | v_mentee · M · v_mentor | Всегда есть (fallback вектор) |
| exp_sim | Нормализованный стаж | log(years+1)/log(21) | Всегда есть (0 лет → 0) |
| rating_sim | Нормализованный рейтинг | (rating - 1) / 4 | Всегда есть (default 3.8) | 

### 4.3 Нормализация факторов
Каждый фактор нормализуется в [0,1] через границы p5–p95 из реальных пар, а не подобранные вручную константы:
> norm(x) = max(0, min(1, (x - p5) / (p95 - p5)))
